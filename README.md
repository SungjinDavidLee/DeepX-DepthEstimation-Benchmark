# On-Device Vision Inference Benchmark

DEEPX DX-M1, NVIDIA Jetson AGX Xavier, NVIDIA Jetson AGX Thor에서 비전 추론 모델의 지연·처리량·전력을 측정한 기록이다.

객체 검출, 인스턴스 분할, 클래스 무관 분할, 단안 깊이 추정 네 가지 작업을 다루며, 다섯 개 모델을 각 플랫폼에서 실행했다.

측정 절차와 원본 수치를 남기는 것이 목적이다. 플랫폼 간 대조는 조건이 일치하는 항목에 한해 제시하고, 일치하지 않는 항목은 별도로 표기한다.

## 1. 요약

**저전력 조건 (온디바이스 배포 대역)**

| 작업 | DX-M1 (INT8, 3~5W) | Xavier 15W (INT8) |
|---|---|---|
| 객체 검출 | **3.83 ms** | 6.82 ms |
| 인스턴스 분할 | **5.26 ms** | 7.52 ms |
| 깊이 추정 ViT-S | 17.99 ms | **15.29 ms** |
| 깊이 추정 ViT-B | 46.66 ms | **29.38 ms** |

Convolution 위주 모델은 DX-M1이, Transformer 기반 깊이 추정 모델은 Xavier가 빠르다.

**상위 플랫폼 참고**

Thor(120W 모드)는 모든 작업에서 가장 빠르다. 전력 예산이 위 두 플랫폼과 크게 다르므로 같은 표에 두지 않는다. 자세한 값은 [3-3](#3-3-참고--thor-120w-모드)에 있다.

**정성 비교**

동일 영상을 세 플랫폼에서 처리한 깊이 맵 결과 영상은 [docs/qualitative.md](docs/qualitative.md)와 [media/](media/)에 있다. 측정 조건이 본 문서와 다르므로 수치를 혼용하지 않는다.

## 4. 관찰

### 4-1. 작업 유형에 따라 우열이 갈린다

DX-M1과 Xavier를 INT8로 대조한 결과다.

| 작업 | DX-M1 | Xavier 15W | 비 |
|---|---|---|---|
| 객체 검출 | 3.83 ms | 6.82 ms | DX-M1 1.78× |
| 인스턴스 분할 | 5.26 ms | 7.52 ms | DX-M1 1.43× |
| 깊이 추정 ViT-S | 17.99 ms | 15.29 ms | Xavier 1.18× |
| 깊이 추정 ViT-B | 46.66 ms | 29.38 ms | Xavier 1.59× |

Convolution 위주 모델에서는 DX-M1이, Transformer 기반 모델에서는 Xavier가 빠르다.

**가설:** DX-M1의 연산 유닛이 convolution에 최적화되어 있고, ViT 계열의 attention 연산은 메모리 대역폭 제약을 더 크게 받는다. 이번 측정만으로는 확정할 수 없으며, 연산자 단위 프로파일링이 필요하다.

### 4-2. INT8의 효과가 플랫폼마다 반대로 나타난다

FP16 대비 INT8의 GPU 연산 시간 변화다.

| 작업 | Xavier | Thor |
|---|---|---|
| 객체 검출 | 26% 단축 | **19% 증가** |
| 인스턴스 분할 | 30% 단축 | **28% 증가** |
| 클래스 무관 분할 | 36% 단축 | **12% 증가** |
| 깊이 추정 ViT-S | **10% 증가** | 10% 단축 |
| 깊이 추정 ViT-B | 8% 단축 | 14% 단축 |

Xavier는 convolution 모델에서 INT8 이득이 크고 ViT-S에서는 오히려 손해다. Thor는 정반대로 convolution 모델에서 INT8이 느리고 ViT 계열에서만 이득이 있다.

**가설:** Thor의 FP16 경로가 충분히 최적화되어 있어 convolution 연산에서는 양자화·역양자화 오버헤드가 INT8 연산 이득을 상회한다. 캘리브레이션을 수행하지 않은 영향도 배제할 수 없다.

전력은 두 플랫폼 모두 INT8이 낮다. Thor에서 FP16 59~83 W, INT8 48~57 W다.

### 4-3. DX-M1에서는 추론 외 구간이 지배적이다

NPU 태스크 전체에서 순수 추론이 차지하는 비중이다.

| 모델 | 추론 | NPU 태스크 총계 | 비중 |
|---|---|---|---|
| yolov8-n | 3.83 ms | 27.48 ms | 14% |
| yolov8-n-seg | 5.26 ms | 43.77 ms | 12% |
| FastSAM-s | 22.39 ms | 102.89 ms | 22% |
| DAv2 ViT-S | 17.99 ms | 27.40 ms | 66% |
| DAv2 ViT-B | 46.66 ms | 63.94 ms | 73% |

검출·분할 모델에서 D2H 전송과 출력 형식 변환이 추론 시간을 크게 상회한다. yolov8-n-seg의 NPU 출력은 10개 텐서 합계 9.19 MB이며, PCIe Gen3 x1 링크에서 D2H에만 13.84 ms가 소요된다.

깊이 추정 모델은 출력 텐서가 작아 이 비중이 낮은 대신, CPU 후처리 태스크가 추론보다 크다(ViT-S 47.27 ms, ViT-B 92.12 ms).

### 4-4. NPU 코어 간 부하가 균등하지 않다

DX-M1의 코어별 추론 시간이다.

| 모델 | Core 0 | Core 1 | Core 2 |
|---|---|---|---|
| yolov8-n | 3.81 ms | 5.76 ms | 5.17 ms |
| yolov8-n-seg | 5.23 ms | 8.09 ms | 7.81 ms |
| DAv2 ViT-S | 17.96 ms | 21.29 ms | 21.45 ms |
| DAv2 ViT-B | 46.55 ms | 61.74 ms | 61.25 ms |

Core 0이 가장 짧고 나머지 두 코어가 더 길다. 배치 크기 1에서 코어 간 부하 분배가 균등하지 않은 것으로 보이나 원인은 확인하지 못했다.

### 4-5. 지연 분포

Jetson 두 플랫폼 모두 p99가 평균의 1.01~1.13배 범위다. Thor가 상대적으로 변동이 크지만 절대 지연이 짧아 실용상 문제가 되는 수준은 아니다.

`dxbenchmark`는 min/max/평균/변동계수만 제공하고 백분위수를 제공하지 않는다. DX-M1의 지연 분포는 동일한 형태로 확인할 수 없었다.

### 4-6. 재현성

Thor FP16을 두 차례 측정한 결과다.

| 모델 | 1차 | 2차 | 차이 |
|---|---|---|---|
| yolov8n | 0.848 ms | 0.854 ms | 0.7% |
| yolov8n-seg | 0.928 ms | 0.940 ms | 1.3% |
| FastSam-S | 1.223 ms | 1.237 ms | 1.2% |
| DAv2 ViT-S | 1.161 ms | 1.214 ms | 4.6% |
| DAv2 ViT-B | 2.007 ms | 1.999 ms | 0.4% |

본문에는 표본이 더 많은 2차 값을 사용했다.

Xavier yolov8n FP16도 두 차례 측정하여 9.266 ms와 9.275 ms로 0.1% 차이를 확인했다.

## 5. 한계

이 측정을 인용할 때 아래를 함께 고려해야 한다.

### 5-1. 전력 모드가 일치하지 않는다

| 플랫폼 | 전력 예산 |
|---|---|
| DX-M1 | 3~5 W (칩 스펙, 고정) |
| Xavier | 15 W (`MODE_15W_DESKTOP`) |
| Thor | 120 W |

장비 설정 변경 권한이 없어 통일하지 못했다. Xavier를 MAXN으로, Thor를 70W(최저 모드)로 재측정하면 조건이 개선되나 수행하지 않았다.

특히 **Thor의 결과를 다른 두 플랫폼과 직접 비교하면 안 된다.** 전력 예산이 8~40배 차이난다.

### 5-2. TensorRT 버전이 다르다

Xavier 8.5.2, Thor 10.16.2다. JetPack에 종속되어 있어 변경할 수 없다. 두 Jetson 간 성능 차이에는 하드웨어 세대 차이와 컴파일러 개선이 함께 포함되어 있으며, 이를 분리할 수 없다.

### 5-3. Raspberry Pi의 전력을 측정하지 않았다

내장 전력 센서가 없다. `dxrt-cli --status`는 NPU 전압(750 mV)과 온도만 보고하며 전류를 제공하지 않는다. 문서에 기재한 3~5 W는 칩 제조사 스펙이며 실측값이 아니다.

### 5-4. INT8 캘리브레이션을 수행하지 않았다

3장의 Jetson INT8 수치는 `trtexec --int8 --fp16`으로 빌드한 엔진에서 측정했으며 캘리브레이션 데이터셋을 제공하지 않았다. 지연·처리량·전력 측정에는 유효하나 **정확도는 보장되지 않는다.**

실제로 이 엔진의 출력 품질을 확인한 결과 **깊이 추정 모델에서 출력이 붕괴했다.** 화면 전체가 단일 색상에 가깝게 압축되어 깊이 구분이 불가능한 수준이었다. 캘리브레이션을 적용하자 정상 계조가 회복되었으며, 속도는 변하지 않았다(4.05 ms → 4.20 ms, 측정 편차 범위).

상세는 [docs/qualitative.md](docs/qualitative.md) 4장에 있다.

DX-M1은 벤더 컴파일 시점에 캘리브레이션이 적용되어 있어 출력이 정상이다. 따라서 **3장의 INT8 비교는 "캘리브레이션된 DX-M1" 대 "무보정 Jetson"의 대조**이며, 속도 측면에서는 유효하나 이 비대칭을 인지하고 인용해야 한다.

### 5-5. FastSAM의 입력 해상도가 다르다

DX-M1은 1024×1024, Jetson은 640×640이다. 픽셀 수가 2.56배 차이나므로 이 작업은 플랫폼 간 비교에서 제외했다.

### 5-6. 모델 출처가 다르다

DX-M1은 벤더가 사전 컴파일한 `.dxnn`을, Jetson은 공개 ONNX를 자체 빌드한 엔진을 사용했다. 그래프 범위가 완전히 일치하는지 확인하지 못했다. 상세는 [docs/models.md](docs/models.md)에 있다.

### 5-7. 정확도를 측정하지 않았다

mAP, 깊이 오차 등 정확도 지표는 측정 범위에 포함하지 않았다.

### 5-8. 열 조건을 통제하지 않았다

주변 온도와 방열 조건을 기록하지 않았다. 장시간 실행 시 스로틀링 영향을 배제할 수 없다.
